## 1. RATIO / BIDI ANALYSIS (read this before writing a single equation)

### 1a. The ratios themselves — all UNSPACED, none flip

Every ratio in this range is written **without spaces around the colon**, so per the unspaced rule it
is one EN run and does **not** reverse in RTL. Verified on the rendered PDF page in every case.

| slide | STORED in XML | RENDERS on the page | sentence names first | correct? |
|---|---|---|---|---|

| 11 | `1:4` | `1:4` | זהב (gold) → 1, כסף → 4 | ✔ |

**Build rule:** keep them unspaced exactly as the deck writes them, and still put each one inside an
LTR isolate (`.ratio` / `dir="ltr"`) so a later copy edit that adds a space cannot silently reverse
it. `check_conventions.py`'s ratio-bidi check asserts the outcome, so an isolate is free insurance.

### 1b. The feedback EQUATIONS — stored REVERSED, render CORRECT. Do not copy the stored string.

Every equation in every feedback popup is stored in **visually-reversed logical order**, because the
author typed it into an RTL paragraph and read back what the screen showed. In RTL the digit runs are
level 2 and the neutral ` = `, ` : `, ` · ` between them resolve to the embedding R level, so the whole
token sequence reverses on render.

**If you paste the stored string into a `dir="ltr"` span you will ship the equation backwards.**
Write the RENDERED form.

| slide | popup | STORED (XML) | RENDERS (page) | build as | math ok? |
|---|---|---|---|---|---|
| 4 | both | `4 = 3 : 12` | `12 : 3 = 4` | `12 : 3 = 4` | ✔ |
| 4 | both | `16 = 4 · 4` | `4 · 4 = 16` | `4 · 4 = 16` | ✔ |
| 8 | both | ` 4 = 9 : 36. ` | `36 : 9 = 4` | `36 : 9 = 4` | ✔ |
| 8 | both | `<m:oMath>4⋅4 = 16</m:oMath>` | `4 · 4 = 16` | `4 · 4 = 16` | ✔ |
| 9 | both | `9 = 3 : 27` | `27 : 3 = 9` | `27 : 3 = 9` | ✔ |
